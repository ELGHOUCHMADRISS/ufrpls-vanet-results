UFRPLS Protocol

Utility-Function Routing with Physical Layer Security for VANETs
Author: EL-GHOUCHMA DRISS Framework: INET 4.x / OMNeT++ 6.x Ref: Chai et al., Electronics 2023 Package: vanetsim.routing.ufrpls Date: 2026-07-01

⚡1. Protocol Overview

UFRPLS is a Physical Layer Security (PLS)-aware greedy forwarding protocol for Vehicular Ad-hoc Networks (VANETs). It extends the classic GPSR protocol by replacing the simple closest-to-destination next-hop criterion with a composite utility function that balances Secrecy Capacity and hop distance.

Core Algorithm — Key Equations

ε_ij = CS_ij^α × d_ij^β [Eq.1 — Utility function; α + β = 1]
C_ij = log₂(1 + Pt × |h_ij|² / σ²) [Eq.2/3 — Channel capacity, FSPL]
h_ij = (λ / (4π × d_ij))² [Free Space Path Loss channel gain]
CS_ij = max(C_ij − C_ie, 0) [Eq.4 — Secrecy Capacity vs. eavesdropper e]
j* = argmax{ ε_ij } [Eq.5 — Optimal next hop selection]
Waiting Mechanism (Algorithm 2): When no neighbour with CS > 0 exists, the datagram is queued and reinjected after an exponentially increasing wait window (tw₁ = 130 µs, doubling each retry), bounded by total threshold T = 65 ms. If the threshold is exceeded, the packet continues to be queued and retried (carry-and-forward behaviour).

PLS Channel Calculations

calculateChannelCapacity(senderPos, receiverPos) → double
constEq. 2/3 — Chai 2023Called by: calculateSecrecyCapacity()

Implements Shannon capacity under Free Space Path Loss. Distance is clamped to ≥ 1.0 m to avoid division-by-zero at co-located nodes.

d = ||receiverPos − senderPos|| (min 1.0 m)
pathLoss = λ / (4π × d)
|h|² = pathLoss²
SNR = Pt × |h|² / σ²
C = log₂(1 + SNR)
flowchart TD A([calculateChannelCapacity]) --> B[d = Euclidean distance] B --> C{d < 1.0?} C -- yes --> D[d = 1.0] C -- no --> E D --> E[pathLoss = wavelength / 4pi*d] E --> F[channelGain = pathLoss^2] F --> G[SNR = transmitPower * channelGain / noisePower] G --> H([return log2 1+SNR])
calculateSecrecyCapacity(senderPos, nextHopPos) → double
constEq. 4 — Chai 2023Uses globalPositionTable

Computes the worst-case Secrecy Capacity of the sender→nextHop link against all known eavesdroppers. Uses globalPositionTable (not local) so that nodes outside the eavesdropper's radio range still compute correct CS values — this is mandated by Chai et al.'s global knowledge assumption.

C_ij = calculateChannelCapacity(sender, nextHop)
for each eavesdropper e in globalPositionTable:
  C_ie = calculateChannelCapacity(sender, e_pos)
  CS = max(C_ij − C_ie, 0)
return min(CS over all e) [worst-case multi-eavesdropper]
flowchart TD A([calculateSecrecyCapacity]) --> B[Cij = calculateChannelCapacity sender nextHop] B --> C[eavesdroppers = globalPositionTable.getEavesdropperAddresses] C --> D{list empty?} D -- yes --> E([return Cij]) D -- no --> F[minCS = Cij] F --> G[for each eavesdropper e] G --> H[ePos = getEavesdropperPosition e] H --> I[Cie = calculateChannelCapacity sender ePos] I --> J[CS = max Cij-Cie, 0.0] J --> K{CS < minCS?} K -- yes --> L[minCS = CS] K -- no --> M[next e] L --> M --> G G --> N([return minCS])

Next-Hop Selection

findGreedyRoutingNextHop(destination, ufrplsOption) → L3Address
Core Algorithm — Chai Alg.1 + Eq.1,4,5Range = 200 m

Implements the full utility-based next-hop selection in a single pass over all neighbours:

  1. Filter by communication range R = 200 m
  2. Compute CS via calculateSecrecyCapacity()
  3. Skip candidates with CS ≤ EPSILON
  4. Compute utility ε = CS^α × d^β (inlined)
  5. Track best (highest utility) candidate
  6. Emit csSignal and update routeMinCS
The standard GPSR "closer to destination" geographic filter is intentionally absent — Chai Algorithm 1 does not use it. The utility function naturally guides packets forward because larger d_ij increases ε_ij when β > 0.
flowchart TD A([findGreedyRoutingNextHop]) --> B[selfPos = mobility->getCurrentPosition] B --> C[init bestAddr=unspec, bestUtil=-1, foundAny=false, foundSecure=false] C --> D[for each neighbor in neighborPositionTable] D --> E[neighborPos = getPosition] E --> F[hopDist = Euclidean distance] F --> G{hopDist > 200m?} G -- yes --> H[skip, next] G -- no --> I[foundAny = true] I --> J[CS = calculateSecrecyCapacity selfPos neighborPos] J --> K{CS <= EPSILON?} K -- yes --> H K -- no --> L[foundSecure = true] L --> M[d = max hopDist 1.0] M --> N[utility = pow CS alpha × pow d beta] N --> O{utility > bestUtility?} O -- yes --> P[bestUtility=utility, bestCS=CS, bestAddr=neighbor] O -- no --> H P --> H --> D D --> Q{foundAny?} Q -- no --> R([return unspecified]) Q -- yes --> S{foundSecure?} S -- no --> T([return unspecified]) S -- yes --> U[totalHops++, secureHops++] U --> V[emit csSignal bestCS] V --> W{bestCS < routeMinCS?} W -- yes --> X[setRouteMinCS bestCS] W -- no --> Y X --> Y([return bestAddr])

Waiting Mechanism (Algorithm 2)

queueForWaiting(Packet *datagram) → Result
Algorithm 2 — Exponential Backoff

Implements the exponential-backoff waiting mechanism. On first call for a datagram, initialises window to tw₁. On each subsequent call, doubles the window. Schedules a WaitingRetryTimer that will reinject the datagram. Always returns QUEUE.

tw₁ = 130 µs (initial window)
T = 65 ms (total budget)

if currentWindow == 0: init tw = tw₁
if totalWaited + tw > T: clamp tw to remaining budget
schedule reinject in tw seconds
totalWaited += tw
currentWindow *= 2
flowchart TD A([queueForWaiting]) --> B[get or create WaitingState for datagram] B --> C{currentWindow == 0?} C -- yes --> D[currentWindow = tw1, totalWaited = 0] C -- no --> E D --> E{totalWaited + window > threshold T?} E -- yes --> F[clamp: window = T - totalWaited] F --> G{window <= 0?} G -- yes --> H[reset window = tw1] G -- no --> I E -- no --> I H --> I[delay = currentWindow] I --> J[totalWaited += delay] J --> K[currentWindow *= 2 exponential backoff] K --> L[create WaitingRetryTimer with datagram as context] L --> M[scheduleAt simTime + delay] M --> N([return QUEUE])

📐10. Mathematical Foundations

Utility Function (Eq. 1)

ε_ij = CS_ij^α × d_ij^β, α + β = 1, default α = β = 0.5

Higher α → favour security (CS)
Higher β → favour geographic progress (distance d)

Channel Capacity (Eq. 2–3)

h_ij = λ / (4π × d_ij) [FSPL amplitude response]
SNR_ij = Pt × h_ij² / σ²
C_ij = log₂(1 + SNR_ij) [bits/s/Hz]

Pt = 0.01 W (10 dBm)
σ² = 3.981×10⁻²¹ W (−174 dBm)
λ = 0.05085 m (5.9 GHz VANET band)

Secrecy Capacity (Eq. 4)

CS_ij = max(C_ij − C_ie, 0) [vs. single eavesdropper e]
CS_ij = min_e{ max(C_ij − C_ie, 0) } [worst-case multi-eavesdropper]

CS > 0 ⟹ physical layer secrecy is achievable on this link
CS = 0 ⟹ eavesdropper has equal or better channel; link is insecure

Algorithm 2: Exponential-Backoff Waiting

tw₁ = 130 µs (initial window)
T = 65 ms (total threshold)

Round k: delay_k = tw₁ × 2^(k-1)
Cumulative after k rounds: tw₁ × (2^k − 1)

When totalWaited + delay > T:
clamp delay to T − totalWaited (carry-and-forward; packet not dropped)
