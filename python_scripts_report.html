01

run_all_simulations_9.py

simulations/ · 644 lines · Runner

Purpose

Batch orchestrator for the complete experiment matrix. Iterates over all (protocol × density × alpha × speed × position × repetition) combinations, patches route files, and launches OMNeT++.

Input Files

FileRole
omnetpp_5pos_full.iniSimulation configuration with all named configs
traffic_{N}veh_{speed}_rou.xmlRoute files — eavesdropper position is injected per run
OMNeT++ binary (opp_run)Simulator executable

Execution Matrix

for protocol in ["UFRPLS", "GPSRCS"]:
  for N in [20, 40, 60, 80, 100]:
    for speed in ["slow", "fast"]:
      for alpha in [0.1..0.9] # slow: all; fast: {0.3,0.5,0.7}; GPSRCS: N/A:
        for rep in [1..5]:
          for pos in ["e100","e300","e500","e700","e900"]:
            patch_route_xml(pos)        # inject departPos into vehicle00
            launch_omnetpp(config, seed=rep)

Output Files

results/UFRPLS-{N}veh-{speed}-a{alpha}-{pos}-rep{r}.sca
Scalar results per UFRPLS run
results/GPSRCS-{N}veh-{speed}-{pos}-rep{r}.sca
Scalar results per GPSRCS baseline run
results/logs/{config}-rep{r}.log
Per-run console output
ℹ️

DEST_VEH mapping: {20:19, 40:39, 60:59, 80:79, 100:99} — the last vehicle index is always the sink. Alpha sweep: slow scenarios test all α∈{0.1, 0.2, …, 0.9}; fast scenarios only α∈{0.3, 0.5, 0.7}.

Project Utility

The entry point for the entire experiment. Enforces reproducibility through fixed seed-set values per repetition, systematic file naming, and eavesdropper position injection via regex. Without this script, the 1250+ individual simulation runs would require manual launch.

analyze_results_5pos.py

simulations/ · 1004 lines · Primary Analysis

Purpose

The core analysis engine. Parses all .sca files, handles both scalar formats (A and B), averages across 5 eavesdropper positions, and generates all Chai et al. paper figures plus new diagnostic plots.

Format A vs. Format B .sca Parsing

FormatExampleParser Function
A — single line scalar …vehicle[3].routing secrecyCapacity 2.45 get_scalar(veh_id, name)
B — stat block statistic …routing secrecyCapacity:stats
field mean 2.45
field stddev 0.88		 get_stat_field(veh_id, stat, field)
⚠️

Position extraction: The eavesdropper position tag (e.g., e500) is extracted from the filename via regex -(e\d+)[-_]. It does NOT appear in the configname attribute inside the .sca file.

Averaging Logic

average_over_positions(data):
    group by (protocol, N, alpha, speed)
    for each group:
        collect data from each of {e100, e300, e500, e700, e900}
        mean = avg across 5 positions
        record per-position extremes (min/max) for error bars

Input Files

All results/*.sca files in the working directory.

analyze_results_5pos_per_rep.py

simulations/ · 159 lines · Analysis — Per Repetition

Purpose

Wrapper around the primary analysis functions, stratified by repetition number. Generates a complete figure set for each of the 5 repetitions (rep1–rep5) to detect run-to-run variability.

Input / Output

Detail
Inputresults/*.sca — filtered by rep number in filename
Output dirresults/plots_5pos_by_rep/rep{N}/
Files per rep~14 PNG figures + avg_5pos_rep.csv + raw_rep.csv
Total output~75 PNG files + 10 CSVs across 5 reps

Project Utility

Validates that no single repetition is an outlier. If rep3 shows dramatically different CS values, it signals a simulation anomaly (partial .sca from a SUMO crash). Also verifies that random eavesdropper positions produce consistent ensemble statistics across seeds.

analyze_results_5pos_per_rep_per_pos.py

simulations/ · 184 lines · Analysis — Finest Granularity

Purpose

Finest-grained analysis tool. Produces a complete figure set for each (repetition × eavesdropper position) combination — 25 slices total. No averaging whatsoever.

Key Difference

Disables the _add_pos_extremes monkey-patch from the primary script since each data slice has only one eavesdropper position — there is no min/max envelope across positions to compute.

Input / Output

Detail
Inputresults/*.sca filtered by (rep, position) from filename
Output dirresults/plots_5pos_by_rep_pos/rep{N}/{pos}/
Files per slice~14 PNG (suffix _rep{N}_{pos}) + 2 CSVs
Total output~350 PNG files + 50 CSVs across 25 slices

Project Utility

Debugging tool for anomalies in specific (rep, pos) pairs. If averaged results show a dip at e700, this script isolates which exact slice causes it. Also verifies the eavesdropper position scan produces a monotonic CS profile along the highway.

plot_per_vehicle.py

simulations/ · 369 lines · Diagnostic

Purpose

Generates a bar chart of Secrecy Capacity per vehicle ID for each .sca file. Identifies which vehicles produce the highest/lowest CS and detects spatial anomalies (e.g., a relay position that consistently hits CS=0 due to proximity to the eavesdropper).

Vehicle Role Color Coding

Vehicle IDRoleBar Color
vehicle[0]Eavesdropper■ Red
vehicle[1]Source■ Green
vehicle[2..N-2]Relay■ Blue
vehicle[N-1]Destination■ Purple

Plot Content

  • Bar height = mean CS (bits/s/Hz)
  • Error bar = ±1 standard deviation
  • ▲ marker = maximum CS observed for that vehicle
  • ▼ marker = minimum CS (≥0 by the max(·,0) formula)

Output Files

results/per_vehicle_plots/{stem}_per_vehicle.png
One bar chart per .sca file
results/per_vehicle_plots/per_vehicle_summary.csv
Tabular: mean/std/min/max per vehicle per file

Project Utility

Reveals the spatial CS distribution along the highway. Vehicles near the eavesdropper's position show lower bars; distant vehicles show higher CS. Useful when averaged results are unexpectedly low — determines if the problem is localized or global.

analyze_all.py

_maps/pls/ · 64 lines · Map Utility

Purpose

Validation utility run from _maps/pls/ after any route file change. Checks that all traffic_*_rou.xml files meet simulation requirements before a batch run is launched.

Checks Performed

CheckMethodFailure Consequence
Eavesdropper gapFind nearest relay on each side of vehicle00Gap too small → SUMO collision on startup
Average relay spacingSort relay positions; compute mean differenceToo large → routing failures due to no forwarding candidate
Braking safetypos + v²/(2×4.5) > 1000 → UNSAFEVehicle cannot stop at junction → SUMO error/crash
Vehicle countCount <vehicle> elementsMismatch vs. expected N → wrong config used

Input / Output

Input: All traffic_*_rou.xml in current directory (glob).

Output: Console text only. No files written.

Project Utility

Pre-simulation gate. Should be run after any route file modification and before run_all_simulations_9.py. Catches two common errors that would otherwise corrupt an entire batch run silently.

gen_80veh_fast_fix.py

_maps/pls/ · 147 lines · Route Generator

Purpose

Programmatically generates traffic_80veh_80-120kmh_rou.xml with a precisely tuned eavesdropper gap and boundary speed safety caps. Replaces error-prone manual XML editing for the most complex route file.

Design Parameters

ParameterValueRationale
Eavesdropper position500.0 mMidpoint — worst-case for multi-hop CS
Gap470m → 510m~30m clear zone prevents SUMO collision
Eastbound relays17 (113–470m) + 21 (510–935m)Even coverage both sides
Westbound relays17 + 22Symmetric
Speed cap at ≥915m22.22 m/s maxBraking safety: v²/2a = (22.22)²/9 ≈ 55m < 85m margin
Lane assignmentlane = i % 4Cycles through all 4 lanes

Input / Output

Input: None (all parameters hardcoded).

Output: simulations/_maps/pls/traffic_80veh_80-120kmh_rou.xml (overwrites existing file)

Project Utility

Fills the gap in auto-generated route files. The 80-vehicle fast scenario requires special tuning because higher density + fast speed creates more collision risk at the boundaries. This script is the canonical generator for that route file.

Alternative version of gen_80veh_fast_fix.py with a different speed pool strategy. Both scripts produce the same output filename and same gap boundaries. Preserved as a development artifact.

Development artifact. Useful if the canonical generator produces unexpected SUMO errors — this alternate version isolates whether the speed pool logic is the root cause.
